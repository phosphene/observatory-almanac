Interoperability
How the Research Board and the Intake Form share state, trigger events, and compose into a single epistemic workspace.
1 · Form → Board (node creation)
Form L1–L3 (intake)
→
L5 confirm fires
→
WorkItem created
→
Node appears on Board
The L5 confirm button POSTs a WorkItem object to the API. The board receives it via WebSocket and instantiates a new node at a calculated position. Status: evaluation queued (if eval route selected) or intake only. In the prototype: simulated via localStorage bridge — completing the form and clicking "Begin evaluation" will create a node here on next load.
2 · Board → Form (node expansion)
Node inspector
→
"Open in form" clicked
→
Form opens with ?uri=…
→
L1 pre-filled
Each node carries its full intake record (L1–L3 data). Clicking "Open in form" navigates to the intake form with the node's URI as a URL parameter. The form loads the node's data into L1–L3 and allows the researcher to add routes, update the description, or re-submit for evaluation.
3 · Evaluation → Board (results return)
Evaluation completes
→
API push event
→
Node status updates
→
Band + score shown
WCI results are pushed to the board as a NodeUpdate event: { uri, band, score, dimensions }. The node re-renders with its band color and score badge. The inspector shows the full dimensional breakdown. Evaluation results are never generated by the form or the board — they arrive from the evaluation pipeline after content is read.
4 · Board relational context → Evaluation
Node A "builds-on" Node B
→
Eval context for A
→
Includes B's WCI profile
When a node is submitted for evaluation, the board sends its connection graph alongside the intake record. A work that "builds on" another can carry that work's WCI dimensional profile as citation context — the evaluator sees not just the claim, but what it is built on and how that foundation scored.
WorkItem schema
WorkItem {
  uri: string // woodchipper.wiki/{type}/{slug}
  title: string | null
  objectType: ObjectType // Scientific case | Observation | …
  researcherType: string
  domain: string | null
  hope: string | null // researcher's stated intent
  routes: RouteId[] // committed routes from L3
  labels: string[] // subject classification codes
  status: EvalStatus // intake-only | eval-queued | evaluating | results-ready
  evalResult: EvalResult | null
  entryText: string // researcher's own words from L1
  submittedAt: ISO8601
}

EvalResult {
  band: STRONG | DEVELOPING | EARLY | PRE-SCIENTIFIC
  score: number // 0–100, WCI only
  dimensions: DimScore[] // 9 dimensions, each 0–10
  completedAt: ISO8601
}
